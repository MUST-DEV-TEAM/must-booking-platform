Keep existing independent plans, nullable-date base rules, dated absolute overrides and room overrides. Add derived plans, priority adjustments, date-cell prices, mandatory taxes/fees, lifecycle/version metadata and operation receipts. Existing bookings and issued signed quote tokens are never repriced or backfilled. New quote nightly snapshots carry the complete calculation components as additive JSON fields; existing consumers can still read date/amount and the grand total. Payment/refund/cancellation/auth/Clock adapter/WordPress code is unchanged.

## Source, permissions and compatibility

One source per property, resolved by enabled scoped PMS assignment, including failed Clock connections. LOCAL supports editing in every booking mode; Clock never falls back to local prices. Clock UI shows managed in Clock, provider prices only from the existing provider reader for an explicitly requested stay, otherwise Unknown with an explanation. No numeric local price is presented as a provider charge. Existing MUST-owned Clock rate ranking remains the existing setting/route with its existing settings.manage guard; it does not edit Clock prices. No new Clock logic or provider endpoint is invented.

Rates workspace reads require existing rates.manage, matching the sidebar capability. Mutations require rates.manage and verified email; no new capability. Read-only states include unverified email, Clock authoritative pricing and denied access. Existing public/staff pricing endpoints retain their current access boundaries.

All new mutation routes require Idempotency-Key (1-128 non-space printable ASCII). One property row lock serializes related checks/writes. Same actor/normalized intent/key replays atomically; changed intent reusing a key returns 409. Edits/lifecycle changes require current record version; base bulk writes require current property pricing version and a matching preview token. Every successful change stores before/after audit and receipt in the same transaction, and increments the property pricing revision. Legacy local rate-plan/rule/room-override write paths must use the same source/transaction/receipt/version safeguards rather than bypassing v2. Trusted local seed calls may generate their own internal operation key; HTTP calls must supply one. Existing read fields remain; version is additive.

## Money and evaluation rules (explicit assumptions)

- The platform's existing NUMERIC(12,2) monetary precision is retained: two decimal places, no FX. New configuration accepts decimal strings, not numeric JSON money. Percentage values have at most two decimal places (basis points). BigInt minor-unit arithmetic is used throughout the pure evaluator; no floating monetary arithmetic. Unsupported currency precision fails visibly rather than inventing an exchange or rounding convention.
- Entry is **tax-exclusive**. Customer grand totals include all active mandatory charges. Charge display Included means bundled into the displayed room price; Added means separately described, while both are already in the grand total. It never changes the underlying tax basis or causes a charge to be counted twice. No tax rate or statutory applicability is pre-filled; activation requires property confirmation.
- Every intermediate nightly result and each charge is rounded to the nearest minor unit, halves away from zero (half-up for non-negative amounts). Fixed decimal adjustments are exact. Negative final accommodation/charge totals, overflow or missing nights reject pricing; no silent clamp. Sum rounded nightly totals for the stay. Allocate a once-per-stay charge to the first applicable night so nightly amounts exactly equal the signed grand total.
- Order: independent room override, else manual daily price, else legacy dated absolute override, else nullable-date base; then one highest-priority matching pricing adjustment; then derived-plan adjustment; then mandatory fixed charges; then percentage charges. No stacking of pricing adjustments. Equal-priority overlapping matching adjustments fail activation and evaluation, including identical values. Lower-priority overlap is allowed and explained. Legacy weekday absolute rules retain Sunday=0; new rule schedules use ISO Monday=1 through Sunday=7.
- A derived plan references one independent plan in the same property/currency; no chains/cycles or cross-currency derivation. Percentage adjustment applies to the adjusted accommodation price. Fixed per-person-night adjustment uses adults plus children (no invented child ages/exemptions). Base-plan-scoped adjustments propagate to its derived plan; derived-specific adjustments compete by the same priority rule.
- Rule/plan conditions: property-local arrival date for min/max stay and booking lead time; date schedule/weekday per sold night. Effective ends are inclusive; stays/checkouts are exclusive. Flat per-adult-night uses adults; per-person-night uses adults plus children; per-stay is per quoted room reservation, not per multi-room order. Age-specific exemptions and whole-order fee allocation are not supported.
- Percentage accommodation charges use accommodation after rule and derived plan. Percentage booking-subtotal charges use that accommodation plus mandatory fixed charges. Percentage charges do not compound on one another. Charges have target types/plans, Website/Staff channels and effective schedules. Draft/Archived items do not affect prices. No implicit taxes are assumed when none are configured.
- Plans have Draft/Active/Archived states, a stable generated code, structured Room only/Breakfast/Half board/Full board meal plan, room-type scope and Website/Staff channels only. One Active fallback exists whenever any active local plan exists. Existing active plans are retained; the earliest existing active independent non-Clock plan becomes fallback. Existing missing-price configurations remain visible as issues and fail when priced. Fallback cannot be archived before replacement; a parent cannot be archived while active derived plans depend on it. Codes cannot change after use (the UI keeps generated codes read-only).
- New plan publication validates usable pricing/scope; schedules can still have later uncovered dates, which the issues/coverage engine reports. Currency cannot change after price configuration or booking use. Existing independent prices are not rewritten by migration. Active rule/charge edits need a change reason; history comes from scoped audit snapshots.
- Bulk base editing sets fixed amounts for selected types/dates/weekdays, at most 1,000 cells before filtering, atomically. A daily price overrides dated/all-year base without destroying their history; reset removes the daily override. All-year base editing uses the existing nullable-date record. Past dates are view-only in the editor. Preview compares exact before/after values and must be re-run after revision changes.
- Pricing coverage/issue validation uses the configured advance-booking horizon (inclusive last arrival) rather than silently stopping at 90 days; absent a horizon, show bounded coverage and mark the unbounded portion Unknown. Issues are derived from saved configuration and the same evaluator, with stable codes; no speculative revenue, invented provider freshness or fake assignment workflow.

## API contract

Base: `/tenants/:tenantId/properties/:propertyId/pricing`.

| Method / route | Body/query | Result |
| --- | --- | --- |
| GET `/` | None | source/readOnly/timezone/today/bookingMode/pricingVersion, scoped room types, plans, base records, rules, charges, derived issues and coverage metadata; Clock local price collections not exposed as provider prices |
| GET `/calendar` | startsOn (default today), days 7/14/30, ratePlanId | Rows of type/date with final amount strings, currency, status, components/errors; same evaluator; Clock Unknown unless explicitly loaded from provider |
| POST `/preview` | roomTypeId, ratePlanId? (LOCAL required), roomId?, startsOn, endsOn, adults, children, channel Website/Staff | Pure local result/explainer, or existing Clock quote reader result marked authoritative provider; no reservation/write |
| POST `/plans` | Editable plan fields | New Draft/version 1 |
| PATCH `/plans/:id` | Fields, version, changeReason when active | New version; stable code |
| POST `/plans/:id/{activate,archive,duplicate,fallback}` | version; fallback includes previous fallback ID/version | Validated lifecycle/copy/fallback result |
| POST `/rules`, `/charges` | Typed fields described above | New Draft/version 1 |
| PATCH `/rules/:id`, `/charges/:id` | Fields, version, changeReason when active | Updated record/version |
| POST `/{rules,charges}/:id/{activate,archive,duplicate}` | version | Validated action/result |
| POST `/base-prices/preview` | plan/type IDs, dates or all-year mode, weekdays, amount string, operation set/reset | Advisory before/after, valid/errors and token/revision; invalid totals are rejected again under the apply lock; reset only daily overrides |
| PUT `/base-prices` | Same intent, version and previewToken | One atomic capped write, audit and receipt |
| GET `/history/:kind/:id` | Scoped UUID/kind | Scoped audit snapshots and actor/time |
| GET `/issues` | None | Saved-state issues from the same health logic used by accommodation pricing readiness; stable codes, scope and suggested navigation |

Existing `/rate-plans` and subroutes retain response fields and gain version metadata; HTTP writes require keys and existing-record versions. Errors use scoped 404, 400 PRICING_INVALID, 403 PRICING_READ_ONLY, 409 PRICING_VERSION_CONFLICT / PRICING_PRIORITY_CONFLICT / PRICING_PREVIEW_STALE / IDEMPOTENCY_KEY_REUSED; authentication/capability failures stay 401/403. No source-text behavioral tests.

## Migration and rollback

Additive scoped daily prices, adjustments, charges and operation receipts with tenant_id/property_id, composite scoped FKs/PKs, constraints and forced RLS. Add lifecycle/derivation/version columns to plans, versions to base/room overrides and a pricing revision to properties. Re-runnable migration; no existing booking/quote money is updated. Roll back application first, retain/export new records/receipts; a pre-feature reader must not be deployed while new derived/charge configurations are active because it cannot reproduce those totals. No destructive rollback is executed.


## Implemented contract details and assumptions

- Amounts and percentages are JSON strings. Identifiers are scoped UUIDs; dates are `YYYY-MM-DD`. Plan/adjustment/charge fields use camelCase as returned by the workspace. New writes use a 1-128 printable-character `Idempotency-Key`. The body `version` is mandatory on existing-record writes; base bulk uses property `pricingVersion`. Receipt hashes include actor and normalized intent. Property `FOR UPDATE` serializes new and legacy local mutations; scope, version, audit and receipt commit together. Same-key retry replays before version validation; a different body with that key conflicts. No automatic receipt expiry.
- Plan fields: name, description, currency, pricingBasis independent/derived, basePlanId, adjustmentKind percentage/per_person_night, adjustmentValue, roomTypeIds, channels website/staff, mealPlan room_only/breakfast/half_board/full_board, minStay/maxStay/minAdvance, publicationStartsOn/publicationEndsOn. Empty scope arrays mean all current and future targets. Currency/basis/parent/code are immutable after creation; generated `RP-` codes use the first 12 UUID hex characters. Lifecycle is Draft/Active/Archived. First active independent/local offer becomes fallback; fallback cannot be archived/deactivated/deleted. Replacement checks both versions. Duplicate copies independent absolute base/daily/room prices to a fresh Draft; separately scoped adjustment/charge records are not copied.
- Rule fields: name, note, mode percentage/fixed, value, currency (null for percentage), roomTypeIds/ratePlanIds, startsOn/endsOn, ISO weekdays 1-7, priority 1-100, minStay/maxStay/minAdvance/maxAdvance. Higher priority wins; ties are blocked even for the same value. Parent-scoped rules also apply to derived offers. Drafts never affect checkout. Active edits require `changeReason`. For plans/charges an empty channel scope is invalid; the default is Website and Staff. Adjustment rules apply across the selected plans without a separate channel filter. Legacy absolute-rule weekdays retain their original 0-6 representation.
- Charge fields: name, note, basis percentage_accommodation/percentage_subtotal/per_adult_night/per_person_night/per_stay, value, currency (null for percentages), display included/added, confirmed, roomTypeIds/ratePlanIds, channels, startsOn/endsOn. `confirmed` must be true before activation; no legal rate is suggested. Percentage-subtotal basis includes accommodation plus fixed mandatory charges, excluding all percentage charges. All applicable mandatory charges appear once in the total regardless of disclosure. Fixed adjustments/charges apply only to matching-currency plans, explicitly disclosed in the editor; no currency conversion. No age tiers, exemptions, optional extras or whole-order fee allocation.
- Base bulk body: ratePlanId, roomTypeIds (nonempty), allYear, startsOn/endsOn (exclusive for daily edits), weekdays, operation set/reset, amount, reason; apply adds version/previewToken. Cap 1,000 potential type/date cells before weekday filtering. All-year replaces the single legacy nullable-date base; date ranges write daily overrides. Reset removes daily/room overrides and reveals the underlying price, never deletes base configuration. Past dates are read-only. Preview returns decimal-string before/after changes and up to 100 dated invalid-total errors; apply recomputes under lock and is all-or-nothing. Preview samples one adult, minimum plan stay, and schedule/weekday boundaries for all-year edits; checkout always evaluates the actual stay/occupancy.
- Room override editing reuses keyed/versioned PATCH or DELETE `/rate-plans/:planId/rooms/:roomId/price-override`, with absent-row version 0. No room assignment or booking rules change. The same transaction/audit guard protects these legacy routes.
- Health is the pure `pricing-health.ts` shared by Rates issues/coverage and LOCAL Accommodation pricing readiness. Coverage evaluates published room types; setup readiness also evaluates Draft room types so pricing does not prevent publication. Both use the complete finite advance horizon with boundary/weekly-cycle sweeps. A ready type has at least one active scoped offer with usable example prices and no missing/invalid example dates; it is not a stock or every-occupancy guarantee. Unbounded coverage is a labeled 365-day sample. Clock readiness retains its existing provider setup checks; no local health substitutes for provider prices.
- Activation validates scope/parent and the first seven relevant arrival weekdays for usable base prices. Full-horizon health remains visible after publication; unusable affected dates fail closed at quote/catalog. This permits deliberate seasonal price coverage rather than blocking an entire plan because it has an off-season gap.
- Reads require rates.manage for the new workspace; legacy plan-list reads retain calendar.view for staff booking selection. New mutations also require verified email. No new capabilities. Clock source is an enabled property Clock assignment even when failed/disconnected; failure never switches to local prices. Workspace/calendar expose no local monetary collections as Clock prices. Provider preview and MUST-only rate priority retain the existing Clock readers/settings route; no provider implementation changes or automatic UI provider probes.
- Additive public contract: quote `nightlyRates[]` can now contain `components[]` with `{kind,id,version,name,amount,display?}`. Kinds are base/rule/plan/charge; amount is a signed decimal string and display is included/added for charges. `total` and each nightly `amount` already include mandatory charges. Signed quote JSON is copied unchanged into new bookings. Dated public catalog offers are filtered by the same evaluator (one adult/no children example); no-date catalog metadata remains advisory. Clock catalogs suppress local offers. WordPress rendering of component breakdown and structured meal/channel data is deferred; no plugin files changed.
- Shared UI is the six-tab Rates workspace, generic PriceGrid/PriceBreakdown, RecordDirectory, versioned dialogs, lifecycle confirmations, quick peek/detail/activity, active-saved-price explainer and explicit read-only/empty/error states. External channels, payment-term editing, speculative revenue, issue assignment, arbitrary unsaved simulation, imports and provider diagnostics remain hidden (dashboard gaps G192-G196). Existing property payment/cancellation terms remain authoritative.

The explainer quotes Active saved plans only; Draft/Archived details show an activation explanation rather than an unusable quote control. The UI does not simulate unsaved or inactive offers. Room-override reasons are carried in the versioned legacy write intent and audit record.
