# Milestone 11: Clock PMS+ Adapter (Basic Integration)

Status: In progress
Depends on: Milestone 4 (booking domain/`PmsProvider`); [ADR-0026](../../decisions/ADR-0026-tenant-integration-connections.md) (tenant-owned integration connections — this milestone builds that foundation, then Clock on top of it); reference material: `docs/source/clock-pms-integration.pdf`

**Carried forward from Milestone 2 (Task 7, 2026-07-28):** Milestone 2's Free-plan limit enforcement could not gate PMS connections — no PMS-connection endpoint existed at all yet. When this milestone builds Task 2's tenant Integrations UI (the actual "connect a PMS" mutation point), add enforcement of `plans.pms_enabled` there: a plan without PMS access must have connection attempts rejected outright (feature gate, not a count), per ADR-0007.

## Goal

A first working `ClockPmsProvider`, sandbox-validated, covering the core loop: connect, catalog sync, availability, and booking create/update/cancel. This is deliberately **basic**, not the full production-grade integration the source brief specifies (full webhook reconciliation, WAF handling, complete observability, all deliverable documents) — that hardening is Milestone 12 and beyond. Done means: a real Clock sandbox account can be connected, its catalog synced, and a booking created/cancelled through `ClockPmsProvider`, end to end.

## Kickoff notes (2026-08-04)

- **No real Clock sandbox credentials exist in this repo or the source brief** — confirmed by a full read of `docs/source/clock-pms-integration.pdf` (9 pages + appendices). The brief itself expects the team to obtain sandbox access separately and verify live. The owner confirmed sandbox access already exists; credentials will be supplied when Tasks 6 and 16 (the two tasks that make real Clock calls) are reached, not needed for the rest.
- **Implementation is being done directly by Claude, not dispatched to Codex** — explicit owner exception (Codex usage temporarily unavailable), same as the TanStack Query migration. Same verification rigor applies: every task gets build + lint + Prettier + full test suite before being marked Done, and Claude marks Done (no external report to cross-check against, since there's no separate implementer).
- **Not held to exactly 10 tasks** (per ADR-0023) — 16 tasks below, sized for reviewability over an arbitrary round number, per the owner's explicit instruction this kickoff.
- The source brief (Albanian) was read in full; section references below point at specific, verified content, not paraphrased guesses. Where the brief itself leaves something undecided (e.g. the exact Digest Authentication mechanics, which endpoint is authoritative for availability — both explicitly listed as open items in section 38), the task's acceptance criteria says so and defers to sandbox verification, per the brief's own `CONFIRMED_BY_DOCS` / `CONFIRMED_IN_SANDBOX` / `CONFIRMED_BY_CLOCK_SUPPORT` / `ASSUMPTION` / `NOT_SUPPORTED` classification (section 39).

## Explicitly not included (deferred to post-Milestone-12 hardening backlog)

- Full reconciliation jobs (source brief section 22), WAF-suspicion circuit breakers, complete observability/alerting (sections 12, 28) — narrow booking-creation-timeout reconciliation (section 18's lookup-before-retry) is in scope via Task 10; the scheduled/generic reconciliation job system is not.
- `CLOCK_RECONCILIATION.md`, `CLOCK_SECURITY_REVIEW.md`, `CLOCK_RUNBOOK.md`, the OpenAPI spec, ER/sequence diagrams, and the production activation checklist (section 37's full deliverable list) — written up before any production activation, not required for this milestone's sandbox-only scope. Task 15 covers only the deliverables that document what's actually built in this milestone.
- Any PMS vendor other than Clock.
- Production activation — this milestone is sandbox-only, per the source brief's Definition of Done (section 36).
