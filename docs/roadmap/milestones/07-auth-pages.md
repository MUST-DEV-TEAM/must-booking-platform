# Milestone 7: Auth Pages

Status: In progress — tasks 1-2, 4-9 Done; task 3 changes requested (backend/DB solid and independently verified, guard component still needs test coverage — not closed by task 8, see task 8's note); task 10 not started
Depends on: Milestone 1 (Tenancy & Auth Core — backend auth API); ADR-0020 (Platform Admin vs. Tenant dashboard routing); the Figma "00 — Base & Components" design system (already reviewed, see Milestone 9's notes)

**Inserted 2026-07-31**, ahead of the (renumbered) Platform Admin Dashboard and Tenant Admin Dashboard milestones. `apps/web` today has no real designed UI at all: `app/page.tsx` is a bare signup form, there is no login page, no forgot/reset-password page, and no `/platform` route — confirmed by inspecting the actual code, not assumed. The existing `app/dashboard`, `app/dashboard/[tenantId]` (with property/room/rate management) and `app/email-verification` pages are unstyled functional scaffolding built incidentally for Milestones 2-3's E2E tests, not designed UI — this milestone doesn't need to throw them away, but does need to give them (and everything after) a real, shared visual foundation.

## Goal

`apps/web` gains its first real UI: a shared component library/design-token foundation in code, a login page, the existing signup/email-verification flow restyled onto it, forgot/reset-password, and role-based post-login routing per ADR-0020 (`PLATFORM_ADMIN` → `/platform`, everyone else → ADR-0010's existing `/dashboard` tenant-picker flow). Done means: a user can sign up, verify, log in, reset a forgotten password, and land on the correct dashboard route for their role — all through real, designed pages, with a component library in place for every later `apps/web` milestone to consume rather than re-derive.

## Explicitly not included

- Actual dashboard content — the Platform Admin dashboard's real screens are Milestone 8, the Tenant Dashboard's real screens are Milestone 9. This milestone only gets a user logged in, restores/resets access, and routes them correctly; `/platform` gets a placeholder landing page here, not real content.
- Dark mode — the design system itself notes "Light theme active · dark mode not yet defined"; ship light-only, dark-mode tokens are a future pass.
- Restyling the WordPress plugin's own `wp-admin` settings screen — different stack entirely (native PHP), out of scope everywhere, not just here.

Task 6 below includes adding that method + wiring the call, mirroring the existing verification-email pattern exactly — small, no ambiguity.

- **No browser E2E infra exists in `apps/web` yet** — only Vitest for unit/component tests (`apps/web/vitest.config.ts`). Task 9 introduces Playwright, matching how every other milestone's "E2E test" task means driving the real running thing, not a mock.
- **`packages/ui` doesn't exist yet** (confirmed: `packages/` currently has only `domain-contracts` and `shared-types`) — task 1 is a genuinely new workspace package, not an addition to an existing one.
